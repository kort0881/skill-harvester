# Skill Harvester

Автоматическая GitHub-база Agent Skills с AI-отбором через Groq.

## Что делает

- Раз в неделю ищет новые публичные `SKILL.md` на GitHub.
- Сохраняет исходные материалы и метаданные источника.
- Каждый день анализирует кандидатов через Groq.
- Оценивает качество, уникальность, полезность, безопасность и применимость.
- Публикует только прошедшие минимальные пороги.
- Раз в месяц объединяет похожие skills в один canonical skill.
- Ведёт локальную библиотеку в `library/skills/` и индекс `library/index.json`.

## Быстрый старт

```bash
git clone https://github.com/YOUR_GITHUB_USERNAME/skill-harvester.git
cd skill-harvester

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
```

В `.env` укажи:

```env
GROQ_API_KEY=...
GITHUB_TOKEN=...
```

Запуск вручную:

```bash
python run.py collect --limit 10
python run.py analyze --limit 5
python run.py consolidate --limit 2
python run.py build-readme
```

## GitHub Secrets

Открой:

`Repository → Settings → Secrets and variables → Actions → New repository secret`

Добавь:

| Secret | Обязателен | Назначение |
|---|---:|---|
| `GROQ_API_KEY` | Да | Ежедневный AI-анализ и месячная консолидация |
| `GITHUB_TOKEN` | Нет | GitHub Actions выдаёт встроенный token автоматически; персональный token нужен в основном для локальных запусков и увеличения лимитов |

> Не добавляй ключ Groq в код, workflow-файл или обычный Git commit.

## Права workflow

Открой **Settings → Actions → General → Workflow permissions** и выбери
**Read and write permissions** — иначе workflow не сможет закоммитить найденные и проанализированные skills обратно в репозиторий.

## Модели Groq

Значения меняются в GitHub Secrets/Variables либо через `.env`:

```env
GROQ_ANALYSIS_MODEL=openai/gpt-oss-120b
GROQ_CONSOLIDATION_MODEL=openai/gpt-oss-120b
```

Варианты:

- `openai/gpt-oss-120b` — основной вариант для глубокой оценки и объединения.
- `openai/gpt-oss-20b` — дешевле/быстрее для лёгкого потока.
- `groq/compound` — подходит для agentic-задач со встроенными инструментами.
- `groq/compound-mini` — более быстрый агентный вариант.
- `qwen/qwen3.6-27b` — альтернативный reasoning-вариант.

## Автоматические расписания

- Сбор: воскресенье, `06:17 UTC`.
- Анализ: каждый день, `07:31 UTC`.
- Консолидация: первое число месяца, `08:43 UTC`.

GitHub Actions может запускать scheduled workflows с задержкой, особенно при высокой нагрузке GitHub. Для гарантированного ручного запуска используй вкладку **Actions** → нужный workflow → **Run workflow**.

## Данные

```text
data/raw/          # исходные SKILL.md
data/candidates/   # очередь, история и state
data/reports/      # отчёты запусков
library/skills/    # опубликованные skills
library/index.json # машиночитаемый индекс
```

## Критерии отбора

- Уникальность: skill не повторяет банальные общеизвестные советы, несёт отдельную ценность.
- Структурное качество: чёткие шаги, входы/выходы, примеры, проверка результата.
- Практическая применимость: понятно, для какой задачи и как использовать.
- Полнота: инструкция доведена до конца, без обрыва на общих фразах.
- Воспроизводимость: другой человек или AI-агент может повторить результат.
- Безопасность: нет вредоносных действий, кражи данных, обхода защиты, скрытых команд.
- Поддерживаемость: понятно, как обновлять и адаптировать skill.
- Ясность: нет маркетинговой воды и противоречий.
- Учёт происхождения: источник и лицензия фиксируются в метаданных.
- Широта задач: программирование, DevOps, сети/VPN/proxy, анализ данных, контент, музыка, дизайн, языки, обучение, продуктивность.

## Важно о лицензиях и источниках

Это кураторская система, а не механизм безусловного копирования. Перед публичным переиспользованием, особенно коммерческим, проверяй лицензию исходного репозитория. Метаданные источника и лицензии сохраняются в `metadata.json`.
